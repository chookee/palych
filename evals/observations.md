## Conditions and limitations

Each condition was generated by a separate native agent inheriting the parent
configuration. Cases within a condition shared one batched context. Model IDs,
sampling settings, and seeds were not exposed; identical stochastic behavior
cannot be claimed.

The initial pilot covered eight cases. One generator additionally loaded
host-level user context, so that pilot is not a controlled comparison.
The revised pair used the same host-level user context and covered eleven cases.
Across both rounds, all fourteen single-turn case IDs have paired replies.
Normal host instructions remained active. This is not a clean-room test of
the skill across platforms or models.

Editorial assessment was performed with condition labels visible. No human
readers participated. These observations therefore support identifying defects
and useful examples, not a general effectiveness claim.

## Findings and changes

The initial skill output sometimes left a pivotal term unexplained, repeated a
completed explanation, and treated a successful proposed diagnostic check as
proof of a cause. The instructions were refined to address those observations:
a term's presence in a question does not establish knowledge; a summary should
add meaning; diagnostic success may support a hypothesis without isolating it.

In the revised skill replies:

- Russian and English cache explanations introduced what a cache stores before
  relying on the term. Both preserved the uncertainty about speed.
- The request/queue/handler explanation kept the actors distinct and omitted
  the earlier redundant recap.
- The error explanation described a successful retry as support for the
  hypothesis, rather than proof.
- Ordered instructions preserved the failure condition and command literals.
- Short answers remained short; the formal notice retained its own style.
- The protected-literal case retained the command, path, quotation, explicit
  prohibitions, and the exact 20 MB acceptance boundary.

Baseline replies were already clear in many cases, including short answers,
progress, conditions, and the revised error explanation. The cache definitions
were a useful editorial difference; most other comparisons were ties or
presentation tradeoffs. No overall win rate or quality score is reported.
A hypothetical payment example remains an area to watch: distinguish the same
effect from promises about implementation or identical response content.

## Verification status

Frontmatter, naming, evaluation JSON, package-local links, and archive integrity
are checked during packaging. Repository guidance validation and its existing
tests cover the registry and documentation integration. These checks do not
verify comprehension or guarantee instruction retention by a host.

Sequential session-probe observations are recorded separately in
[session results](results/session.json). Context compaction, actual installation
in other hosts, and behavior across model versions remain untested.

Reader comprehension testing has not been performed. Follow the
[evaluation protocol](README.md), collect unclear passages and content answers,
revise, and retest before making a reader-understanding claim.

### Persistence and tooling evidence

- Fourteen adapter/builder tests pass: fresh-process state restoration on compact,
  resume and clear; session off over always-on; reactivation; quoted/embedded
  commands; malformed state; hashed session IDs; host manifests; overwrite guard;
  helper control; concurrent sessions and a failed atomic commit.
- Independent code review found a partial-update bug in an early adapter draft.
  The default and session overrides now commit in one state file under a lock.
  The reviewer confirmed the fix using an actual permissions-based write failure
  and twelve concurrent synthetic updates. Owner settings were not used.
- Seventeen offline evaluation tests pass: masking, pair completeness, observed
  configuration parity, semantic gates, locked judgments, overwrite guards and
  explicitly limited exploratory mode.

These are deterministic helper checks, not a real host compaction test. Real
installation, hook trust, event delivery and model behavior after actual
compaction remain unverified. A confirmed off response alone is not proof of
saved state; a clear reply alone is not proof the adapter ran.

### Masked editorial pilot

The [complete synthetic evidence](results/blind-pilot-2026-10-10/summary.json)
retains raw replies, masked packets, judgments, lock, manifest and revealed map.
The map was withheld from the assessor until judgments were completed and locked.
All public inputs and replies are synthetic; no reader or owner data is included.

Six cases were selected: Russian/English cache explanation and repeated failed
fixes, plus Russian consequential action and access blocker. Each condition used
three new native generation agents. Each agent generated its six cases in one
batched context, giving eighteen paired comparisons. The independent assessor
was another fresh native agent, given only masked A/B packets and the rubric.

Observed aggregate: skill preferred in 7 pairs, baseline in 2, tie in 9.
The assessor marked no semantic failures in either condition. Across repeated
cases: the skill was preferred in English/Russian diagnostic messages and the
Russian blocker; baseline in both cache cases; the deletion-preparation case
tied. This counts this assessor's judgments, not measured comprehension gains.

The useful differences concerned how to interpret a server response or no
response, the limits of the diagnosis, and who can run an unavailable check.
In two cache pairs the baseline explained timing costs more usefully, while the
skill reply mainly repeated hit/miss paths. Ties were common; the baseline was
already clear on many messages. The package does not claim superiority on every
case or replace negative results with a selected success example.

Limitations: the model identifier, sampling parameters, seed and full inherited
base-instruction hash were not exposed and remain null in the manifest. Native
agents inherited the same host configuration without overrides; that does not
verify hidden settings. Generator wrappers were near-equivalent but differed in
skill-loading and file/output paths. Batched cases can affect one another;
repetitions are not independent statistical samples. The assessor used the same
inherited model family, and recognizable style can weaken masking. No human
readers participated. This is an exploratory editorial pilot, not a controlled
full-suite comparison or a significance claim.

## Core compression — 2026-10-10

The 0.3.0 core consolidates repeated instructions while retaining activation,
artifact boundaries, reader knowledge, logical links, natural RU/EN language,
exact values/prohibitions/modalities, agent responsibility and silent repair.
Examples remain optional; evaluations are development-only. Saved hook
acknowledgements apply to the current mode request only.

[Six synthetic replies](results/optimized-core-2026-10-10.json) were generated by
one fresh native agent using only the core and selected prompts. They cover
Russian/English cache explanation, exact values and percentage points, protected
English literals, a third failed fix, and unauthorized deletion. Requested IDs
that did not exist were replaced with recorded actual IDs before generation.

The parent assessed the replies with labels visible. No meaning error was
observed: the 20 MB boundary, date/time, explicit prohibitions, command/path/error
and uncertainty survived; a server response did not establish valid credentials.
This is a small exploratory regression check, not a blind comparison, full
20-case evaluation or measured improvement in reader comprehension.

The skill-creator quick validator could not run: both available Python runtimes
lack PyYAML. No dependency was installed. Repository frontmatter/link checks and
explicit naming/placeholder checks are used instead; this does not imply the
bundled validator passed.

### Adapter and payload checks for 0.3.0

Twenty-three adapter/builder tests passed. Added coverage includes repeated
activation, every supported context boundary, changed core hash, reactivation,
helper transitions, legacy state, missing core, malformed emission markers
and executable compact metadata. Seventeen blind-tool tests and eleven guidance
checks passed. The registry validator checked 43 tracked files.

[Static payload counts](token-usage.md) show a smaller core and shorter control
acknowledgements. These are reference text counts, not subscription savings.
Emission markers attest helper output, not actual model delivery; live host
compaction and human comprehension remain untested.
